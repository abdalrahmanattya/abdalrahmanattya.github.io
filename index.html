About

Strategy on one side, working systems on the other.

I'm a Principal Cloud Architect based between Copenhagen and London. I specialise in designing secure, scalable and cost-efficient cloud platforms — the kind an engineering team can still operate six months after the architecture diagrams are filed away.

My background spans cloud architecture, platform engineering, DevOps automation, security, data platforms and AI/ML workload enablement. I've led cloud-native initiatives across SaaS, video management, retail and technology environments.

Most recently at Milestone Systems I led the cloud architecture for Project Hafnia, a collaboration with NVIDIA focused on enabling visual AI model development using high-quality, regulation-compliant video data — owning the architecture from concept through production deployment.

I work hands-on. Alongside client engagements I designed and built the Secure Self-Service Cloud Platform — an open-source internal developer platform for provisioning policy-compliant Kubernetes environments on AWS or Azure, with policy-as-code, deterministic review artifacts and fail-closed deployment workflows.

I work AI-assisted, and I'm deliberate about it. Agentic tooling has changed how much ground one architect can cover — scaffolding infrastructure code, interrogating a policy surface, producing the review artifacts that used to take a week. What it hasn't changed is who is accountable for the decision, and that is the part I keep.

The through-line: I take a problem nobody has framed yet, turn it into a decision someone can disagree with in writing, and then build the thing.

Secure Self-Service Cloud Platform

Open source · MIT · v1.0.0
Designer & author · github.com/abdalrahmanattya

An internal developer platform for requesting secure, policy-compliant Kubernetes environments on AWS or Azure. Developers request through a portal, API or CLI; every request is evaluated against policy and turned into a deterministic, reviewable proposal. Execution is deliberately handed off to protected, approval-gated workflows.

  • Policy engine with readable feedback across ownership, cost, network, encryption, logging and expiry.
  • Deterministic evidence — request IDs, fingerprints and content hashes, so reviewers verify exactly what will be created.
  • Fail-closed GitHub workflows bound to an exact proposal hash, with approval gates and short-lived OIDC credentials.
  • Separate AWS and Azure Terraform roots, each with provider-native network, identity, encryption and budget design.
